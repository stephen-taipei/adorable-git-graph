# RD 診斷試用方案（未實測）

本文件是執行方案，沒有招募、使用量或市場驗證結果。

招募 10 位不同資歷、每週有實際 Git 診斷需求的 RD。以難度相近且答案已由完整 Git fixture 核對的任務組，交錯本專案與 RD 慣用 CLI／VS Code／Git client 的使用順序；單題固定逾時 5 分鐘。任務包含分歧、相同分支、merge parent、rename、binary、無共同祖先、shallow、缺物件、fork PR、權限／限流。不完整資料的 unknown 任務單獨統計。

建議決策門檻：已知答案任務成功率 ≥95%；相對慣用工具，中位完成時間縮短 30%；預期 unknown 的案例全部正確處理；10 位 RD 至少 6 位在第 3、4 週各自主完成一次真實診斷任務。工程 fixture 的確定答案必須 100% 符合 Git；這與人員任務成功率不同。

自願紀錄只含匿名試用代碼、週次、任務代碼、工具順序、完成秒數、成功／失敗／逾時／非預期 unknown，以及自主重複任務次數。不要收集 repo 內容、名稱、路徑、token、SHA 或自由文字原始診斷摘要。未選擇提供資料的操作不記錄，不新增遙測。

分析必須同列失敗、逾時與非預期 unknown，不只計算成功案例的時間。以每位 RD 的配對時間及整體中位數呈現，樣本小時保留個別差異。若結果未達門檻，先根據任務失敗原因修正查詢正確性、可發現性或等待時間，再決定 P2 的優先序。此試驗不能代表整體市场留存或 PMF，也不能推導部署失敗率或交付週期改善。
